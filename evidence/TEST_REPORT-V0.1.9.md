# AnimeFlow V0.1.9 测试报告

## 实际来源与审查

输入是上传的 V0.1.5 ZIP（5 个源码/说明文件）；没有取得 V0.1.8 的代码，因此没有假定后续版本功能存在。
官方规范：https://github.com/bangumi/server/blob/master/openapi/v0.yaml ，保存快照于 evidence/bangumi-v0.yaml。
实测日期：2026-10-10；测试环境：Linux、Python 3、Node.js 24、Chromium 153。
这是阶段一完成及阶段二部分完成的交付，不是最终 Windows 桌面版。

## 根因及修复

1. POST 搜索的 air_date 是比较表达式数组，不是两个纯日期。真实对照原参数 total=0，修正为 >=2024-01-01 与 <2024-04-01 后 total=253（limit=3）。原/修正响应分别保存为 search-original.json 和 search-corrected.json。
2. POST sort 不支持 date；GET /v0/subjects 的 sort 则支持 date/rank，不能混用接口规范。
3. 原服务器未放行 GET /v0/subjects，直接迁移前端会得到 403。
4. 原每日放送兜底使当前季度偶尔成功，历史季度失败。已移除季度查询的 calendar 兜底。
5. 原类型和排序控件不参与查询，搜索仅覆盖加载页面。修复为先取季度全部月份分页，再全量筛选/排序和分页显示。
6. 缓存原来只有一个季度槽位；现有 SQLite 按年份季度保存，失败保留旧数据，浏览器缓存按季度区分。
7. 真实 GET 返回部分 date=null，排除并记录，不能据此推断季度。不是伪造发布日期。

## 尚未完成或无法验证

- 全库搜索、完整特别篇分类、所有国家地区的权威分类，未完成；社区标签缺失会影响筛选。
- 实际视频平台更新动态、日历、逐条未读标记未完成；已移除容易误导的预计下一集占位动态。
- 日期已到不证明平台上线。未验证同日精确开播时间和临时停播；无法确认日期的剧集锁定。
- 授权片源、嵌入许可、内置播放、自动进度、上一/下一集、字幕和弹幕尚未完成。
- 弹弹play官方要求申请 AppId/AppSecret，尚无项目凭证，也未调用鉴权接口。文档 https://doc.dandanplay.com/open/ 。未发送申请邮件。
- 追番/历史仍在 localStorage；只有季度缓存使用 SQLite。
- Rust 工具链、Windows 构建运行环境不存在；没有构建 EXE、没有 Tauri 安装包、未测 Windows 实机。start.bat 仅为启动脚本，未在 Windows 执行。
- 只验证本环境能连接 Bangumi，不代表已经测遍中国大陆各运营商。
